## 2. 自动验证的数据

做法：原型用命令行把文件转给它预览（与 OmniZip 调用的路径相同），页面渲染完成后回报时间；经 WebView2 远程调试检查媒体是否在播放，用 PrintWindow 截图确认画面。全程不发送按键。

### 2.1 速度（预热窗口，作为对照）

| 阶段 | 耗时 |
|---|---|
| 冷启动到页面就绪 | 约 420 ms |
| 收到请求到窗口出现（预热窗口） | 0.3–7 ms |
| 文本 136k 字首屏 | 40–60 ms |
| 图片（800×500 PNG） | 约 12 ms |
| PDF（WebView2 内置查看器） | 60–70 ms |
| 视频首帧 | 30–120 ms |
| 系统预览程序（Word / Excel，首次） | 0.8–1.4 s（其中创建 0.45–0.93 s） |

### 2.2 格式支持

| 类型 | 可以 | 不行 |
|---|---|---|
| PDF | WebView2 内置查看器，经 `look://` 协议加载，带缩放、翻页、搜索 | — |
| 视频 | mp4（H.264、H.265、AV1）、webm（VP9）、mkv（H.264）、mov（H.264） | avi、wmv |
| 音频 | mp3、flac、ogg（Vorbis）、opus、m4a、wav | wma |
| Office | Word、Excel 系统预览程序，代理进程中运行，以文件路径初始化 | — |

- mkv、mov 能否播放取决于里面的编码；样本是 H.264 + AAC。
- 关闭 GPU 时 H.265 无法播放，H.264、AV1、VP9、PDF 不受影响（软件解码）。
- PowerToys 注册的 PDF 预览程序在宿主里显示空白（未深究：PDF 走 WebView2，不需要它）。
- WebView2 的 PDF 工具栏带打印、保存，M2 用 `HiddenPdfToolbarItems` 精简。

### 2.3 内存（私有内存合计，含全部 WebView2 进程）

| 配置 | 空闲（窗口隐藏） | 预览过一次后 | 代价 |
|---|---|---|---|
| 预热窗口，GPU 加速 | 约 200 MB | 约 240 MB | — |
| 预热窗口，隐藏时设低内存目标 | 同上 | 同上 | 只缩小工作集，私有内存不变 |
| 预热窗口，关闭 GPU | 约 108 MB | 约 118 MB | H.265 无法播放 |
| **方式 C：只常驻钩子** | **1.3 MB** | 预览时见 §2.6，关闭即释放 | 每次预览冷启动 |

Omni Look 进程本身只有约 6 MB，大头是 WebView2 的 GPU 进程（105–135 MB）。方案 §1.3 原定的 80 MB 在预热窗口下达不到，2026-11-11 选定方式 C，并按扩展名决定是否开 GPU。

### 2.4 选中项读取

- `IShellWindows` 枚举到全部资源管理器窗口；`IShellBrowser::GetWindow` 返回的是标签页窗口（`ShellTabWindowClass`），可以按标签区分。
- 当前标签按"顶层窗口的第一个 `ShellTabWindowClass` 子窗口"判断，多标签时是否可靠尚未覆盖。
- 桌面经 `FindWindowSW(SWC_DESKTOP)` 读取正常。

### 2.5 方式 C：每次预览冷启动

每种文件 3 轮，每轮从启动预览进程开始计时，到内容渲染完成（页面回报）为止；视频开 GPU，其余加 `--disable-gpu`，两种模式各用一个 WebView2 数据目录。

| 文件 | GPU | 启动到内容出现 | 预览时内存 |
|---|---|---|---|
| 文本（168 KB） | 关 | 330–353 ms | 132 MB |
| 图片（PNG） | 关 | 304–318 ms | 126 MB |
| PDF | 关 | 344–362 ms | 247 MB |
| 音频（mp3） | 关 | 358–365 ms | 137 MB |
| Word（系统预览程序） | 关 | 989–1008 ms | 125 MB（不含预览程序进程） |
| 视频 H.264 | 开 | 424–530 ms | 395 MB |
| 视频 H.265 | 开 | 453–493 ms | 370 MB |

21 轮全部成功，关闭后内存全部释放。

### 2.6 遇到的问题与对方案的修正

- **页面就绪的竞态**：页面注册事件监听是异步的；先报告"就绪"再注册完监听，紧接着发来的文件会丢失，表现为偶发的空白窗口（冷启动时约三成）。改为监听注册完成后才报告就绪，此后 27 轮冷启动无一失败。M1 照此实现。
- **关闭预览窗口导致钩子失效**：原型中预览窗口是唯一窗口，点 × 关闭后整个进程退出、钩子随之消失（手动测试时遇到）。方式 C 中钩子在常驻代理里，预览进程退出不受影响。
- **系统预览程序跑在窗口线程上**：原型在窗口线程上同步创建和初始化预览程序（约 1 s），这期间窗口无响应；预览程序若卡住，窗口会一直卡住。M2 放到独立线程并设超时（方案 §3.1、§12）。
- 窗口尺寸按**目标显示器**的缩放计算（多显示器、不同缩放）；大小与位置用 Tauri 接口设置，只有"不激活地显示"用 Win32。
- 预览窗口显示时置顶（`HWND_TOPMOST`），否则焦点在资源管理器时预览会被它盖住。
- 原型只在方向键之后重读选中项；鼠标点选其他文件时的跟随要订阅 `SelectionChanged`，放到 M1。
- 用 PrintWindow 截图验证时，截图进程要声明 DPI 感知，否则高缩放下截图被裁切（测试工具的问题，不是程序的问题）。

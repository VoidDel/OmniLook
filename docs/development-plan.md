## 1. 项目概述

### 1.1 目标

Omni Look 是 Omni 家族（[OmniZip](https://github.com/VoidDel/OmniZip)、[Omni Download](https://github.com/VoidDel/OmniDownloadeManager)）的快速预览工具：在资源管理器或桌面选中文件后按 Ctrl+空格（可改为单独的空格），立即弹出预览窗口；再按一次或 Esc 关闭，方向键切换相邻文件。心智与 macOS 的 Quick Look 一致。

同时它是 OmniZip 的预览后端：装了 Omni Look 时，OmniZip 中预览压缩包里的文件交给它显示。

对标产品与差异：

| 产品 | 借鉴 | Omni Look 的差异 |
|---|---|---|
| macOS Quick Look | 空格开关、方向键跟随选中项、不抢焦点 | — |
| QuickLook（QL-Win，GPL-3） | 插件化预览器、命令行调用、第三方文件管理器支持 | MIT 许可，Rust 实现，与 Omni 家族同一套主题；**只参考做法，不复制代码** |
| PowerToys Peek（MIT） | 用系统组件（WebView2、系统预览程序）做预览 | 不需要安装整套 PowerToys（.NET 运行时与 WinUI 3 合计约 230 MB）；Peek 本身拆不出来，见 §2.2 |
| Seer | 预览种类多 | 免费开源 |

卖点：

- **一键就看，平时不占内存**：资源管理器与桌面一按即开（0.5 s 内）；常驻部分只有键盘钩子，约 1 MB。
- **压缩包看得透**：直接使用 OmniZip 的格式库，几十种压缩包格式一按就能看目录树，一键在 OmniZip 中打开。
- **轻**：安装包目标 < 20 MB；所有渲染用系统已有组件（WebView2、系统解码器、系统预览程序）。
- **统一外观**：omni-ui 的主题、强调色、深浅色与窗口材质，与 OmniZip、Omni Download 一致。

### 1.3 非功能需求

| 指标 | 目标 |
|---|---|
| 按键到内容出现（每次启动预览进程） | ≤ 400 ms（不开 GPU 的类型）；视频 ≤ 600 ms（M0 实测 0.30–0.37 s / 0.42–0.53 s） |
| 预览打开时切换文件（同一进程） | 1 MB 文本 / 代码 ≤ 200 ms；12 MP JPEG ≤ 300 ms |
| 快速连按方向键 | 只渲染最后一个，之前的请求取消 |
| 常驻内存 | ≤ 5 MB（只有钩子与管道；M0 实测 1.3 MB） |
| 预览时内存 | 不开 GPU 约 130 MB，视频约 400 MB；关闭预览即全部释放 |
| 键盘钩子开销 | 每次按键 < 1 ms，不触发时零额外工作 |
| 安装包体积 | Windows < 20 MB |

### 1.4 非目标

- 不做编辑器、图片查看器或播放器的替代品：预览只读，复杂操作交给"用默认程序打开"。
- 不做 macOS 独立应用：macOS 自带 Quick Look（§7）。
- 不预览网络内容：不加载远程资源，不联网。

## 2. 技术选型

### 2.1 总览

| 层次 | 选型 | 理由 |
|---|---|---|
| 外壳 | Tauri 2 | 与 OmniZip、Omni Download 相同；WebView2 本身就是 PDF、音视频的渲染器 |
| 前端 | React 19 + omni-ui | 家族共用设计系统与主题 |
| Windows 系统接口 | `windows` crate | 键盘钩子、Shell COM（选中项、视图事件）、预览程序宿主 |
| 代码高亮 | `syntect` | Rust 侧切分语法，只把"类别 + 位置"传给界面；约 200 种语言；界面不插入 HTML |
| 文本编码 | `encoding_rs` + `chardetng` | 与 OmniZip 预览一致（GBK、Shift_JIS 等） |
| 图片 | WebView2 直接显示（在沙箱渲染进程里解码，与 PDF、音视频一样）；WebView 不支持的 TIFF 由 `image` 转成 PNG | 2026-11-11 改：在 Rust 里重编码大图要几百毫秒，冷启动预算放不下 |
| SVG | 作为 `<img>` 显示 | 图片上下文里的 SVG 不执行脚本、不加载外部资源，不需要 `resvg` |
| Markdown | `pulldown-cmark` + `ammonia` | 渲染后再净化，不加载远程图片 |
| 压缩包 | `omnizip-formats`（git 依赖） | 同一作者、MIT；格式覆盖与 OmniZip 一致 |
| PDF | WebView2 内置 PDF 查看器（Windows） | 零体积；在 Chromium 沙箱内解析。M0 验证经自定义协议加载可行，否则换 pdf.js |
| 音视频 | `<audio>` / `<video>` + 支持 Range 的自定义协议 | 用 WebView2 自带解码器；不支持的格式退回"用默认程序打开" |
| Office 等 | Windows 系统预览程序（IPreviewHandler） | 与资源管理器预览窗格相同的效果；需要安装对应软件（如 Office） |

### 2.2 关键决策说明

**为什么不直接调用或打包 PowerToys Peek / QuickLook。** 在 OmniZip 里调用已安装的 Peek、QuickLook 是可行的低成本方案，OmniZip 仍会把它们作为备选（§6.4）。但把 Peek 拆出来打包不现实：PowerToys 0.102 中 Peek 自身约 4 MB，却依赖 .NET 10 运行时（144 MB）、Windows App SDK / WinUI 3（69 MB）、Monaco（13 MB），以及 PowerToys 的设置、遥测等内部库。而 Peek 的各类预览本质上是对 WebView2、系统解码器、系统预览程序的包装，Tauri 应用同样能直接用这些组件，只多几 MB。

**为什么单独成为一个应用，而不是 OmniZip 的一部分。** 快捷键预览需要常驻进程与全局键盘钩子，和压缩软件的生命周期不同；不装 OmniZip 的用户也能用。OmniZip 继续保留轻量的内置预览（文本、图片、十六进制），装了 Omni Look 时再交给它。

**代码高亮放在 Rust 侧。** 大文件高亮不阻塞界面；输出只是类别与区间，界面用 `<span>` 渲染，不存在 HTML 注入；颜色映射到 omni-ui 令牌，随主题切换。

## 3. 系统架构

### 3.1 进程与线程

常驻的只有一个不含 WebView 的小进程；预览窗口每次按需启动，关闭即退出（2026-11-11 选定，依据见 [M0 结果](m0-results.md) §2.3、§2.5）。

```
omnilook.exe（常驻代理，单实例，不含 WebView；M0 实测 1.3 MB）
├─ 钩子线程          WH_KEYBOARD_LL + 消息循环；只做"要不要拦下"的快速判断
├─ Shell 线程（STA）  查询资源管理器选中项、订阅选中变化、枚举同目录文件
└─ 管道服务           接收命令行 / OmniZip 的预览请求；与预览进程通信

omnilook.exe --view（预览进程，每次预览启动，关闭预览即退出）
├─ 预览窗口           Tauri + WebView2，不抢焦点地显示
├─ 预览工作线程       读文件、识别类型、生成预览（可取消，只保留最新请求）
└─ 系统预览程序宿主   独立的 STA 线程，不占用窗口线程（M2）
```

- **按扩展名决定 GPU 加速**：视频开 GPU（H.265 只能硬件解码）；其他类型加 `--disable-gpu`，预览时内存约减半。两种模式的 WebView2 启动参数不同，必须用两个数据目录（`EBWebView-gpu` / `EBWebView-cpu`）。
- 预览打开时切到另一种模式的文件（例如从图片切到视频），代理关掉当前预览进程、按新模式重新启动（约 0.5 s）。
- 关闭预览窗口不影响代理；代理没有运行（关闭了开机启动）时，`omnilook preview <文件>` 直接启动预览进程。
- 第二次启动（`omnilook <文件>`）把参数转给已运行的代理后立即退出。托盘图标默认不显示：不带参数再次启动（开始菜单里点 Omni Look）即打开设置窗口（同样是按需启动的进程）。

### 3.2 数据流：按快捷键

```
按下快捷键（默认 Ctrl+空格）
  → 钩子线程：前台是资源管理器 / 桌面、焦点在文件列表、不在输入状态？否 → 放行
  → 是 → 吞掉按键，通知 Shell 线程
  → Shell 线程：取当前窗口（Win11 取当前标签）的选中项与同目录文件顺序
  → 代理：启动预览进程 omnilook --view <文件> --anchor <资源管理器窗口>（视频另加 GPU 模式）
  → 预览进程：页面就绪后识别类型 → 生成 Preview（文本片段 / 图片 / 目录树 / 媒体地址 …）
  → 显示在资源管理器窗口中央，不抢焦点（M0 实测启动到内容出现 0.30–0.53 s）
方向键（焦点仍在资源管理器）→ 资源管理器自己移动选中项 → SelectionChanged 事件
  → 代理经管道把新文件交给预览进程；GPU 模式不同则重启预览进程
```

### 3.3 Rust 模块划分

| 模块 | 职责 | 平台 |
|---|---|---|
| `omnilook-core` | 类型识别（扩展名 + 文件头）、各预览器、资源上限、取消 | 全平台，可单测 |
| `omnilook-win` | 键盘钩子、资源管理器选中项与事件、系统预览程序宿主 | Windows |
| `apps/desktop/src-tauri` | 窗口、托盘、单实例、设置、自定义协议（文件、媒体 Range） | 全平台 |

## 4. 快捷键触发：资源管理器集成

这是整个项目风险最大的部分，M0 先做原型验证。

### 4.1 拦截快捷键

默认快捷键 **Ctrl+空格**（与 PowerToys Peek 相同），设置中可改为单独的空格。

- 不用 `RegisterHotKey`：它会让 Ctrl+空格在所有程序里失效，而中文输入法常用 Ctrl+空格切换中英文。改用 `WH_KEYBOARD_LL` 全局钩子，只在下列条件都满足时吞掉按键，其余情况原样放行：
  1. 前台窗口类名为 `CabinetWClass`（资源管理器）或桌面（`Progman` / `WorkerW`）。
  2. 焦点控件在文件视图里（`SHELLDLL_DefView` 下的 `DirectUIHWND`，桌面为 `SysListView32`）；不在地址栏、搜索框、重命名编辑框中。
  3. 修饰键与设置一致：默认只按住 Ctrl；按住 Alt / Shift / Win 时放行。
  4. 仅单独空格模式：1 秒内没有输入过字母数字（资源管理器的"输入文件名定位"会用到空格）。
- 吞掉的是空格的按下与抬起；Ctrl 本身不拦。资源管理器文件视图里原本的 Ctrl+空格（切换焦点项的选中状态）因此被占用，与 Peek 相同。
- 钩子回调里只做上面的快速判断，其余工作交给别的线程（系统对钩子有超时限制，超时会被移除）。

### 4.2 取得选中项

- `IShellWindows` 枚举资源管理器窗口，按顶层窗口句柄匹配前台窗口；经 `IServiceProvider` → `IShellBrowser` → `QueryActiveShellView` → `IFolderView2` 取选中项（`GetSelection`）与按视图顺序排列的全部项（`Items(SVGIO_ALLVIEW | SVGIO_FLAG_VIEWORDER)`）。
- **Windows 11 标签页**：同一个顶层窗口下有多个标签，各自是一个 `IShellWindows` 条目，要找出当前可见的那个标签（比较各标签的 `ShellTabWindowClass` 子窗口是否可见）。这是已知难点，M0 必须实测。
- 桌面：`IShellWindows::FindWindowSW(SWC_DESKTOP)` 走同样的路径。
- 没有文件系统路径的项（回收站、手机、资源管理器里打开的 zip 文件夹等）：M1 不支持，显示"无法预览"。

### 4.3 预览期间

- 预览窗口以不激活方式显示，焦点留在资源管理器：方向键由资源管理器自己移动选中项，Omni Look 订阅视图的 `SelectionChanged` 事件（`DShellFolderViewEvents`）刷新预览。
- 预览打开时，钩子额外拦下快捷键与 Esc 用于关闭。
- 用户点击预览窗口（滚动 PDF、播放视频）后焦点到 Omni Look：此时左右键由 Omni Look 按 §4.2 取得的视图顺序切换，快捷键 / Esc 关闭并把焦点还给资源管理器。
- 资源管理器窗口关闭或切换文件夹时自动关闭预览。
- 失去焦点时关闭（设置项"失去焦点时关闭预览"，默认开）：代理用 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 监视前台窗口。预览窗口本身、打开它的窗口（跟随的资源管理器窗口；桌面的 `Progman` / `WorkerW`；命令行调用时请求到达那一刻在前台的窗口，如 OmniZip）以及这些窗口打开的对话框都算"仍在焦点内"，前台换成其他任何窗口即关闭。关掉此项后，预览一直保留到按快捷键、Esc 或点关闭。

### 4.4 已知限制

- 管理员权限运行的资源管理器：普通权限的钩子收不到（系统的权限隔离），不处理。
- 安全软件可能对全局键盘钩子告警：正式发布的二进制要签名，文档说明钩子只在资源管理器前台时生效、不记录按键。

## 5. 预览器

### 5.1 类型识别与调度

先看扩展名，再用文件头校验（扩展名与内容不符时以内容为准，如改名的 zip）。每种预览器声明能处理的类型与读取上限；生成过程可取消，连按方向键时只完成最后一个。

| 预览器 | 类型 | 实现 | 里程碑 |
|---|---|---|---|
| 文本 / 代码 | 文本类扩展名、无 NUL 的未知文件 | 编码识别 → 最多 2M 字符；≤ 512 KB 做 `syntect` 高亮，更大的按纯文本显示 | M1 |
| 图片 | png / jpg / gif / webp / bmp / ico / avif / tiff | WebView 经 `look://` 直接显示；TIFF 由 `image` 转成 PNG（大于 4096 px 先缩小） | M1 |
| SVG | svg | 作为 `<img>` 显示（不执行脚本、不加载外部资源）；源码视图 M2 | M1 |
| 压缩包 | OmniZip 能读的全部格式 | `omnizip-formats` 列出目录树、大小、压缩率、加密与否；"在 OmniZip 中打开" | M1 |
| 文件夹 | 目录 | 项数、总大小（后台计算，可取消）、最近修改 | M1 |
| 十六进制 | 其余文件 | 前 4 KB 十六进制 + 文件信息 | M1 |
| PDF | pdf | WebView2 内置查看器，经自定义协议加载 | M2 |
| 音视频 | mp3 / m4a / aac / flac / wav / ogg / opus / mp4 / webm / mov 等 | `<audio>` / `<video>`，自定义协议支持 Range；能否播放以 M0 实测为准，不支持时显示时长等信息并提供"用默认程序打开" | M2 |
| 系统预览程序 | 系统登记了预览程序的类型（Office、Visio、字体、部分 PDF 阅读器等） | 见 §5.2 | M2 |
| Markdown | md | `pulldown-cmark` → `ammonia` 净化；可切换到源码视图 | M2 |
| Office 简易预览 | docx / xlsx（未装 Office 时） | 读 ZIP 内的 XML：docx 抽正文段落，xlsx 显示前若干行表格 | M3 |

每个预览底部固定显示：文件名、大小、修改时间，按钮"用默认程序打开"（Enter）。

### 5.2 系统预览程序宿主（M2）

- 资源管理器预览窗格用的就是这套：类型在注册表 `HKCR\<扩展名>\ShellEx\{8895b1c6-b41f-4c1c-a562-0d564250836f}` 下登记了预览程序的 CLSID。
- 按系统惯例在代理进程 `prevhost.exe` 中运行（`CLSCTX_LOCAL_SERVER`），不把第三方 DLL 加载进 Omni Look 自己的进程。
- 宿主为预览窗口拥有的无边框弹出窗口（不激活，键盘留给页面），按屏幕坐标覆盖在 WebView 的预览区域上，随窗口移动、缩放调整位置，随窗口最小化隐藏；切换文件或关闭时 `Unload`。（不用子窗口：WebView2 的合成层会盖住用 GDI 绘制的子窗口，字体预览程序因此一直看不见。）
- 预览程序在独立的 STA 线程上创建、初始化和绘制，窗口线程只等结果，10 秒没有回应就放弃并换一个新线程；初始化优先用文件路径（字体预览程序需要），其次 Shell 项，最后流（Office 只接受流）。
- 预览程序不处理的按键（Esc、Ctrl+空格、左右键）经 `IPreviewHandlerFrame::TranslateAccelerator` 交回预览窗口。
- 自带预览器认不出的类型（十六进制视图的那类），系统有预览程序就交给它（字体、Outlook 邮件、CAD 等）；Office 等类型在没装对应预览程序时显示文件信息卡片。
- 优先级：Omni Look 自带的预览器优先（更快、主题一致），系统预览程序用于自带预览器不支持的类型；设置中可按扩展名调整。

## 6. 与 OmniZip 的集成

### 6.1 发现

Omni Look 安装时写入：

```
HKCU\Software\OmniLook
  InstallPath      REG_SZ     安装目录
  ProtocolVersion  REG_DWORD  调用协议版本（当前 2，§6.3）
```

另登记 `App Paths\omnilook.exe`，便于其他程序与"运行"对话框调用。OmniZip 读到 `ProtocolVersion ≥ 1` 即认为可用。

### 6.2 调用（协议 v1，M1）

```
omnilook.exe preview <文件> [--title <显示的名称>] [--source omnizip]
```

- OmniZip 先把条目解压到它自己的缓存目录（带上"来自网络"标记），再调用上面的命令；`--title` 显示为"压缩包名 › 包内路径"，而不是缓存路径。
- 同一文件再次调用 = 关闭预览（与 QuickLook 的命令行语义相同），对应 OmniZip 中再按一次预览键。
- 缓存文件归 OmniZip 管理，关闭压缩包或退出时删除；Omni Look 不删除传入的文件。
- 第三方文件管理器（Directory Opus、Total Commander 等）用同一命令集成。

### 6.3 压缩包内左右切换（协议 v2，M2）

Omni Look 2 登记 `ProtocolVersion = 2`。OmniZip 读到 ≥ 2 时额外传入 `--nav \\.\pipe\omnizip-nav-<OmniZip 进程号>-<用户 SID>`（Omni Look 只接受 `\\.\pipe\` 开头的值）。预览窗口里按左右键时，代理在后台线程上经这个管道发送一行 JSON（不阻塞代理）：

```json
{"op":"next","path":"<当前显示的缓存文件>"}
```

`op` 为 `next` 或 `prev`。请求里用的是 OmniZip 交出去的缓存文件路径，而不是条目 id：OmniZip 记得每个缓存文件对应哪个条目，命令行就不必多一个参数。OmniZip 按列表当前的排序找同一文件夹里的相邻文件（跳过文件夹），解压到缓存后回复，并让列表的选中项跟过去：

```json
{"path":"<缓存文件>","title":"<压缩包名 › 包内路径>"}
```

没有相邻文件时回复 `{"end":true}`，出错时回复 `{"error":"…"}`。Omni Look 收到回复时若用户已切到别的文件则丢弃。管道只接受同一用户的连接（DACL），Omni Look 连接时也核对服务端进程属于同一用户。一次只问一个，问的过程中再按方向键会被忽略。

### 6.4 OmniZip 侧的改动

- 设置新增"预览方式"：内置 / Omni Look / 其他预览工具 / 系统程序。"其他预览工具"自动检测 PowerToys Peek、QuickLook、Seer，也可自定义命令（`{file}` 代表文件）。
- 默认：装了 Omni Look 用 Omni Look，否则用内置预览。
- 修复"用外部程序打开"整个文件读进内存的问题，改为流式写入缓存文件（OmniZip 现有问题，与本集成同步完成）。
- 关于页的家族卡片加入 Omni Look。

| 平台 | 方案 |
|---|---|
| Windows | 完整功能（本文档主体） |
| macOS | 不做独立应用：系统自带 Quick Look。改为提供 Quick Look 扩展（`QLPreviewingController`），补上系统不支持的类型，首先是压缩包目录树；OmniZip 在 macOS 上直接调用系统预览面板。与 OmniZip 路线图中"Quick Look 预览扩展"合并实施 |

## 8. 安全设计

预览的文件可能来自网络，按不可信输入处理：

- **解析在内存安全的代码里做**：文本、Markdown、压缩包、TIFF 在 Rust 中解析；界面只接收已净化的结果（文本、语法区间、目录树、PNG）。
- **交给 Chromium 沙箱的是图片、SVG、PDF 与音视频**：它们在 WebView2 的渲染进程沙箱内解码；SVG 只作为图片显示，不执行脚本。
- **第三方预览程序在代理进程中运行**（§5.2），不进入 Omni Look 进程。
- **不联网**：CSP 禁止一切外部连接，`connect-src` 只允许 IPC；WebView 禁止导航到其他页面；Markdown 与 SVG 中的远程资源不加载。
- **资源上限**：文本读取上限、图片边长与内存上限、压缩包条目数上限（沿用 OmniZip 的策略）、生成预览超时。
- **自定义协议**只提供当前预览的文件，用一次性令牌而不是路径访问，不能借此读取任意文件。
- **钩子**不记录、不保存任何按键；只在资源管理器前台时判断。

## 10. 开发路线图

### M0 — 原型验证

用最小的代码验证风险最大的几点，结果写回本文档：

1. 键盘钩子 + 选中项：资源管理器（含 Win11 多标签）与桌面；重命名、地址栏、搜索框、输入定位时不误触发。
2. 预热窗口：按键到窗口出现的耗时；空闲内存。
3. 不抢焦点显示 + `SelectionChanged` 事件跟随方向键。
4. WebView2 经自定义协议加载 PDF；`<video>` 经 Range 协议播放，记录实际可播放的格式。
5. 在 Tauri 窗口里嵌入系统预览程序（docx、xlsx）。

验收：每一项有结论；不可行的项给出替代方案（如 PDF 改用 pdf.js）。

### M1 — 可用版本

- 常驻代理（钩子 + 管道）与按需启动的预览进程（按扩展名选 GPU 模式，两个 WebView2 数据目录）。

### M2 — 完整预览

- PDF、音视频、系统预览程序、Markdown。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Win11 多标签取错当前标签 | 预览了别的标签里的文件 | M0 实测；取不准时退回"只在单标签窗口启用"并提示 |
| 单独空格模式下误拦截（输入定位、重命名） | 打字被吞 | §4.1 的判断条件；默认的 Ctrl+空格不受影响 |
| 每次预览都冷启动 | 比预热窗口慢约 0.3 s | M1 实测体感；不够快再加"关闭后保留预览进程 N 秒"的选项 |
| 预览进程在页面监听就绪前收到文件 | 偶发不显示（M0 遇到） | 页面注册完事件监听后才报告就绪，代理收到就绪再发文件 |
| 系统预览程序卡住 | 预览窗口无响应 | 宿主放在独立线程并设超时；超时则显示"用默认程序打开" |
| 自定义协议下 PDF 不显示 | M2 PDF 方案失效 | 改用 pdf.js（约 3–4 MB） |
| 系统预览程序嵌入不稳定（焦点、DPI、崩溃） | Office 预览不可用 | 代理进程隔离；失败时退回"用默认程序打开" |
| 安全软件对键盘钩子告警 | 用户不敢装 | 代码签名；文档说明钩子只在资源管理器前台时判断、不记录按键 |
| 与已装的 Peek（同为 Ctrl+空格）/ QuickLook 抢快捷键 | 两个预览窗口同时出现 | 启动时检测并提示；设置中可换快捷键 |
